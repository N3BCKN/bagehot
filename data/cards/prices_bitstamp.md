# Data card — ETH/USD one-minute candles, Bitstamp

**Cross-check series.** Its job is to catch a quote-currency mistake, a silent gap or a bad print
in the primary Coinbase series — not to be averaged with it. Both are USD-quoted, so their closes
are directly comparable (`reports/data-validation.md`).

Kraken was the first choice (P06 prompt) and cannot do this job: its REST OHLC endpoint
"[returns] up to 720 of the most recent entries", and older data "cannot be retrieved, regardless
of the value of `since`" (<https://docs.kraken.com/api/docs/rest-api/get-ohlc-data>, read
2026-10-22). Kraken's full history exists only as downloadable CSV archives, which no fetcher can
reproduce idempotently. Bitstamp is USD-quoted, has ETH/USD from 2017, and documents an
arbitrary-range OHLC endpoint.

| page size | 1000 candles — the documented maximum for `limit` |
| why `end` and not `start` | the documentation states that when both `start` and `end` are given, "the end timestamp will be used". Asking by `end` + `limit` is therefore deterministic; asking by `start` would silently depend on which bound the API honours |
| rate limit | documented as 400 requests/second with a default threshold of 10,000 per 10 minutes; the fetcher uses 5/second |
| authentication | none for public market data; the fetcher sends no credentials |
| terms | <https://www.bitstamp.net/terms-of-use/> |

## Known characteristics and how they are handled

- **All numeric fields arrive as strings** (`"timestamp": "1722816000"`, `"close": "2691.10"`).
  The adapter converts timestamps to `int` and prices to `float`; a fixture test pins this.
- **`exclude_current_candle=true`** so a partially formed minute never enters the dataset.
- **Bitstamp pads every no-trade minute with a synthetic bar.** The API returns a candle for
  every minute of the range; a minute with no trades comes back with `volume = 0` and
  `open = high = low = close` equal to the previous close — the venue has forward-filled it.
  Measured at P06: 620,593 such bars of 4,075,200 (15.2%), 620,289 of them exactly at the
  previous close; by year 42.4% (2019), 29.9% (2020), 7.4% (2021), 8.4% (2022), 12.1% (2023),
  11.2% (2024), 3.8% (2025), 3.6% (2026). A zero-volume bar is not an observed price, so
  processing turns it into a gap (`Source.emits_empty_minutes`, counted in the table above).
  Keeping them would store forward-filled prices, which P06 forbids, and would inflate the
  divergence against Coinbase by comparing real trades with stale ones. Coinbase emits no such
  bars (0 zero-volume rows), so after processing both series have the same gap semantics.
- **Real coverage after that is 84.8%** — a markedly thinner book than Coinbase (99.6%).
- **Divergence from Coinbase is itself a measurement.** Median divergence is reported overall and
  separately for 2020-03-12/13, 2021-05-19, 2022-05-09..12 and 2024-08-05, where venue-specific
  dislocations are expected to be largest.
- Timestamps are candle open times, UTC throughout.

## Validation

Same checks as the primary series (`uv run python -m data.validate`), plus its role as the
comparison arm in the cross-source divergence table. The sha256 above is re-checked against the
file on disk on every validation run.

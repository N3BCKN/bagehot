# Data card — ETH/USD one-minute candles, Coinbase Exchange

**Primary price series** for the project (kit correction 7: Coinbase ETH-USD is USD-quoted and is
the primary source; a USDT-quoted series is never mixed into it). Feeds the bootstrap path
generator (P28) and scenarios S2 and S4.

| field | value |

| venue | Coinbase Exchange (Advanced Trade / Exchange public market data) |

## Known characteristics and how they are handled

- **Response order is newest-first.** The endpoint documentation does not state a sort order; the
  live API returns descending timestamps. The adapter sorts every page by timestamp instead of
  trusting the order.
- **Element order is `[time, low, high, open, close, volume]`** — low and high come *before* open
  and close, which is easy to get backwards. A fixture test asserts the mapping
  (`tests/data/test_prices.py`).
- **Missing minutes.** Minutes with no trades are simply absent from the response. They are kept
  absent in the processed file; `reports/data-validation.md` lists every gap with its duration.
  Measured at P06: 12,131 gaps totalling 15,957 minutes (coverage 99.61%); the longest is 394
  minutes on 2026-05-08, which looks like a venue-side outage rather than an empty market.
  Coinbase never returns a zero-volume bar (0 such rows), unlike Bitstamp, which pads every
  no-trade minute (see `prices_bitstamp.md`).
- **Outliers are flagged, never removed.** Large one-minute moves during March 2020 or August 2024
  are the signal this project studies.
- **Timestamps are candle open times**, in UTC throughout. No local time is parsed anywhere in the
  pipeline.

## Validation

`uv run python -m data.validate` checks monotonicity, duplicate timestamps, gaps with durations,
outlier flags (|1-minute log return| > 8 × rolling MAD over 1440 minutes) and the divergence
against the Bitstamp series overall and inside the four named stress windows. It also re-checks
the sha256 above against the file on disk, so a stale card fails the run.
